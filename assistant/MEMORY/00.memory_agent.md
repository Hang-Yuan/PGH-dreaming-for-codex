### 写入授权（两区模型）

**内容层自治（N 级）**：池内新建、升降星、状态迁移、唤醒、合并、衰减、横向统合和行级物理删除，执行后在 dream 流水披露；[用户称呼]可随时推翻。

- 季度归档 LTM / 两 log。

两 log 一律派storage-agent；主会话只定稿语义文本。若连续三次storage-agent限流，只有 `daily-dream` 的 MEMORY_LOG 落账可按现行兜底协议直写，且必须写后验证 U+FFFD=0；其他 log 不扩权。

## 记忆系统结构

### schema 是什么

一条 schema 是预测单元，不是事实：

```text
触发情境（何时调用） → 行动 / 预期（如何行动或预测）
```

- 程序型必须有行动，语义型必须有预期，混合型两者都要有。
- 元数据包括强度、状态、类型、语境与证据指针。
- 能画出真实的“不这样做的人”才是 schema；画不出则是全称重言式。

### 信息流与分流

```text
Codex 用户会话 JSONL（L0，只读）
  ├─ 事件走向：做了什么/选了什么 → 项目主文档、progress、LTM、_本周
  └─ schema 走向：如何判断/为何转向/用户校准
          ↓ 两轴判定（对照现有 schema 全集）
     episodic_memory（1-3★）
          ↓ 周日横向统合；项目快轨/高风险单条为例外
     semantic_memory（4-6★，不注入）
          ↓ 6★ + 跨周稳定≥3周 + C verdict
     USER / SOUL / skill / AGENTS §R
```

工作库与记忆系统在 progress 转向处交叉：项目结论仍留工作库；只有剥掉项目后仍成立的判断模式进入池。

### 代谢对照基线

P 轴是差分，不是孤立打分。dream 判定前必须让现有 schema 全集同时在场：

| 基线 | 比对对象 | 作用 |
|---|---|---|
| `episodic_memory.md` | 新观察是否命中、同构、休眠唤醒 | 升星、查重、合并、唤醒 |
| `semantic_memory.md` | 新观察是否强化或击穿跨情景 schema | semantic 只在代谢期读取 |
| USER / SOUL / AGENTS §R | 是否命中已毕业终态 | 终态命中不重复加权；抵触才进入代谢 |

skill 不进记忆池差分基线；它是已毕业程序终态，由 skill 演化链独立审改。

### 生命周期

```text
L0 会话转写 / progress 转向
  → 两轴差分
  → 单事件候补 / ≥2 独立事件活动
episodic 1-3★
  → 命中升星 / 衰减复审 / 候补到期删除
  → ★★★再命中只标待统合簇
semantic 4-6★
  → 强化 / 修订 / 衰减 / 摘标
  → 毕业提案
身份层终态
```

## 全局参数

### 代谢速度梯度

| 层 | 节律 | 执行者 |
|---|---|---|
| 工作结论 → 工作库 | 节点/日级 | close-node / daily-dream phase A |
| 行为 schema → episodic | 夜间日级 | daily-dream；close-node 为受控例外 |
| 跨情景 schema → semantic | 项目快轨日级 / 普通周级 | daily-dream |
| 身份层 | 月级 | C verdict 后毕业 |

短期记忆就是会话上下文，不另设池。

### 有效工作日

当日 `_本周.md §进展记录` 有实质工作流水，计 1 个有效工作日。纯对话且无工作流水不计。回推时读本周文件，必要时读周归档。

### 逻辑日期

物理 hour < 06:00 → 逻辑日期 = 物理日期 − 1；≥ 06:00 → 同物理日期。

> `06` 是模板默认值，**部署时由 `scripts/install_schedule.py` 按部署者作息改写**（本处与 `AGENTS.md §时间感知` 两处同数）。日界线落在部署者「已睡下、还没起」之间——两点睡的人和十点睡的人，「一天」的分界不同。设错不报错，只会每天有一段工作被归到错误的日子。

适用于 daily-dream、close-node 的日期字段、周次、log 和 `last_dream.md`。逻辑日 D 的物理窗口是「D 日界线」到「D+1 日界线」；固化必须等窗口闭合后运行，故排程设在日界线 + 30 分钟，其处理目标 = 当前逻辑日期 − 1 天（即刚闭合的窗口），不得处理仍开放的当前逻辑日。排程时刻仍按物理时间，不能把逻辑日期填进排程字段。

### 两池容量阈值

| 池 | 健康区 | 预警/红区 | 硬上限 |
|---|---|---|---|
| episodic 活动+复审 | ≤30 | 31-40 预警；>40 周日必须清回 | 无 |
| episodic 候补 | ≤10 软提示 | 超出提示信号洪水 | 7 EWD 无第二证据自删 |
| episodic 休眠 | 不计容量 | 季度审查 | — |
| semantic 活跃组 | ≤5 | 6-7 无动作；8 预警 | 10，强退最低优先项回 episodic |
| 活跃组内项目语境 | ≤3 | 超出退最低优先项到 episodic 休眠 | 3 |

dream 开工必须报两池数量与状态；周日处理红区。

## 提取层

### L0 回放提取规则

L0 是 Codex JSONL，不是记忆文件。

1. 用 `daily-dream/scripts/extract_daily_transcripts.py` 按逻辑日期的 06:00→次日 06:00 窗口提取。
2. 只纳入有效 `thread_source=user` 的主会话；排除 subagent、automation、运行时注入文本和仅由内部控制帧启动的 continuation turn。
3. 当日全部活跃用户会话全量回放，不按轻重日缩深度，不只扫尾段。
4. 缺梦最多补扫最近 3 个有效工作日；更早信号接受遗忘。
5. 每条证据锚点写逻辑日期 + session id + turn id；不把整段聊天复制进池。

### 双走向分流

- 事件走向：由 close-node 或 daily-dream phase A 固化到工作库；phase B 只校验。
- schema 走向：由 daily-dream 做两轴差分与池内代谢。
- 先固化工作事实，再代谢 schema；dream 不用 schema 替代项目正史。

### 两轴判定

P 轴：

| 值 | 定义 |
|---|---|
| 命中 | 观察符合当时 schema 的预测 |
| 击穿 | 观察反向校准或否定预测 |
| 未覆盖 | 当时没有覆盖此类观察的 schema |

C 轴：

| 值 | 定义 |
|---|---|
| 正向确认 | [用户称呼]明确赞同、确认或强化 |
| 反对 | 明确拒绝或不满 |
| 纠正 | 修正局部而非全盘否定 |
| 中性 | 无明确校准 |

提取下限：

```text
P=命中 且 C=中性 → 不提取
其他组合 → 进入代谢判定
```

中间态 schema 的“命中 + 正向确认”是爬星燃料；已毕业终态不是。

### 身份层前置过滤

| 命中对象 | C 轴 | 动作 |
|---|---|---|
| USER / SOUL / AGENTS §R | 中性或正向确认 | 不提取 |
| USER / SOUL / AGENTS §R | 抵触、纠正或击穿 | 进入代谢，不直接改身份层 |
| semantic 活跃组 | 命中+正向确认 | archive 补证并按升星加权 |
| semantic 活跃组 | 击穿 | 标需要修订 |
| 未命中终态/semantic | 任意 | 按提取下限继续 |

## episodic_memory 规则

### episodic 状态机

| 状态 | 进入 | 退出 |
|---|---|---|
| 候补 | 单事件值得追踪 | 第二独立事件→活动；7 EWD 无复现→删 |
| 活动 | ≥2 独立事件过红线 | 升 semantic；7 EWD 无激活→复审；合并/删 |
| 复审 | 活动条目衰减 | 再激活→活动；14 EWD 仍静默→删 |
| 休眠 | 项目语境 semantic 降级 | 命中→唤醒活动；季度无唤醒→删 |

休眠不占活动容量，周日不做普通时间衰减。

### 生成

1. 按预测对象、校准信号与情境域聚合。
2. 写成可复现“情境→行动/预期”。
3. 过抽象红线：≥2 独立事件写活动；单事件写候补。
4. 与全表现有条目查重；深层同构则强化，不新建。

### L0→L1 升格抽象红线

- 形式达标 + ≥2 个不同事件支撑同一类情境，才进活动态。
- 同节点同一事件多次提及不算独立事件。
- 单事件只可进候补；高风险、越权、系统事故和重大安全信号可直升活动，须写复审条件。
- 自检：只看一条证据就能写出 schema，说明只是换句式，不是跨事件抽象。

### 字段

强度 / 状态 / 类型 / 语境 / 创建日期 / 最后激活 / 提取次数 / 触发情境 / 行动模式 / 预期 / 来源指针。语境默认跨情景；项目语境必须写项目名。

### 升星

| 条件 | 动作 |
|---|---|
| 同日重复校准 | 每条每日最多升 1 星 |
| 7 EWD 内再次校准 | +1 星，更新最后激活 |
| 命中休眠 | 唤醒活动，保留星级 |
| 明确击穿 | 重写或建立竞争候选 |
| 跨情景 ★★★ 再命中 | 不直升；提取次数+1，标待统合簇 |

普通跨情景升 semantic 的唯一门是周日横向统合。项目快轨与高风险单条是两条例外。

### episodic 衰减

| 条件 | 动作 |
|---|---|
| 活动 7 EWD 无激活且提取 0 | 转复审 |
| 复审累计 14 EWD 无激活 | 物理删除 |
| 候补 7 EWD 无第二证据 | 物理删除，可日级执行 |
| 提取 1 次且 14 EWD 无再激活 | 转复审 |
| 提取 ≥2 | 不按时间自动删 |
| 提取 ≥5 | 审查合并 semantic 或项目规则 |
| 休眠 | 免时间衰减；季度整批审查 |

活动/复审的 D 类时间衰减只在周日 dream 执行。

## semantic_memory 规则

semantic 是 4-6 星中间工作区，不启动注入。

### 升格判准

必须满足 1、2、4-8；第 3 是分流器：

1. 能写成非机械“预测情境→行动预期”。
2. 跨日/节点/情境复现；高风险、越权、系统事故可单条保留并写复审条件。
3. 抽掉项目仍成立→跨情景；只在同项目成立且符合快轨→项目语境；两者皆否→不升。
4. 能画出真实对照人。
5. 每条独立判断，不一刀切全表。
6. 有 P/C 证据，不是事实正确。
7. 不与身份层、项目正史或 LTM 冲突。
8. 抽象到比现场证据深一层的内在稳定模式。

### 项目语境快轨

- 同项目 ≥3 个有效工作日复现并过判准 1、2、4-8，可日级升 semantic。
- 强制标 `语境：项目名`，活跃组内最多 3 条。
- 出现跨项目证据，周日摘标转跨情景。
- 降到 3 星时回 episodic 休眠；项目重启命中再唤醒。
- 项目语境条目不毕业，须先摘标。

### 升格动作

池内升格为 N 级：查等价 schema→合并或新增→本体与证据先落盘→再处理来源→容量动作→dream 日志披露。

### 横向统合

周日 dream 执行，是跨情景 episodic 升 semantic 的唯一门：

1. 聚类活动+复审条目，不含候补/休眠；优先待统合簇。
2. 按深层结构析母结构并过全部判准。
3. 母结构与证据先落 semantic/archive，再删贡献原料。
4. 再合就画不出对照人时停止，防 over-merge。
5. 不成簇但单条够格者，可在同一周日门内升格。

### 字段与排序

字段：强度（4-6 星）/ 状态（活跃组、备用、需要修订、毕业候选）/ 类型 / 语境 / 预测情境 / 行动预期 / 证据指针。

排序：高风险约束 > 强度 > 最近 14 日命中 > 与当前处境相关 > 未被身份层覆盖。项目语境在项目活跃期上浮，静默期下沉。

### semantic 衰减

| 条件 | 动作 |
|---|---|
| 整周无命中 | -1 星 |
| 被击穿并纠正 | 标需要修订；周日重写或降级 |
| 跨情景降到 3 星 | 回 episodic 活动 |
| 项目语境降到 3 星 | 回 episodic 休眠 |
| 活跃组 8 条 | 预警，可退最低优先项到备用 |
| 活跃组 10 条 | 强退最低优先项回 episodic |
| 6 星且跨周稳定 | 生成毕业候选，等 C verdict |

## 毕业

### 毕业条件

```text
6 星 + 跨周稳定 ≥3 周 + 三路独立蒸馏收敛 + [用户称呼] C verdict
```

高风险纪律可在稳定 2 周时提案，但仍需 C verdict；项目语境条目不得毕业。

### 判型分流

**用户模型语义型 → USER**：写机制句 / 世界观假设 / 触发情境 / 预测动作四件套；反事实反转后行为也必须反转。共享 USER 只提案，不越权落盘。

**程序型按序命中即止：**

| 序 | 出口 | 判别 | 约束 |
|---|---|---|---|
| 1 | hook | 触发可代码化、动作确定 | ≤30 行，单判定+单动作，须沙盒实测 |
| 2 | persona_SOUL | AI 人格/关系稳定模式 | 四件套 |
| 3 | skill | 绑定特定流程域 | 写对应 skill；MetaScale 未 promote 时只产提案 |
| 4 | AGENTS §R | 全局、需判断、高频 | ≤80 字，一次至多 1 条 |

混合型拆开分流，允许不同步毕业。

### 三路独立蒸馏

1. 给三个互不可见 sub-agent 同一最小输入：条目本体、该条 archive 证据、出口规范。
2. 各自独立产出目标形态。
3. 三路一致→收敛；两路一致→多数决并标分歧；三路各异→未熟退池。

### hook 实测验证

收敛实现只放临时沙盒，不进入生效 hooks。再派三个互不可见 sub-agent 独立设计应触发/不触发/边界 case 并实跑。三路全过才生成“已验证”提案。

### 毕业提案格式

条目 ID / 判型与出口 / 蒸馏全文 / 三路收敛报告 / hook 实测报告（如适用）/ 建议落点与替换文本。

### 毕业事务

周日 dream 只生成候选并写 MEMORY_LOG；C verdict 后剥壳写目标；写后移出 semantic 活跃组；完整审计写 semantic_archive + MEMORY_LOG §毕业归档。

---

## MEMORY_LOG 收录边界

- `§操作日志`：每个逻辑日一条 dream 汇总；close-node 直升另写一行。
- `§周复盘`：仅周日 dream 写。
- `§毕业归档`：仅实际毕业事件写。
- 架构、skill、hook、AGENTS 和协议变化写 ITERATION_LOG，不写 MEMORY_LOG。
- `last_dream.md` 只在 pool + archive + log 全部成功后更新。

---

## 协议变更一致性

任何本文件、skill、hook、AGENTS、storage-agent、自动任务或记忆文件头部的协议变化，必须四步闭合：

1. 改单一权威源本体。
2. 扫 `<CODEX_HOME>/` + `<ASSISTANT_ROOT>/MEMORY/` + automation 的引用网络，清残留复制体。
3. 同轮更新 touched 文件 frontmatter/version。
4. 派 storage-agent 追加 ITERATION_LOG。

### 跨文件指针书写规范

- 指针写“文件 + §唯一标题锚点”。
- 锚点必须与目标标题逐字符一致或是唯一连续子串；写前用 `rg` 验唯一命中。
- 标题不带版本号、日期或临时后缀。
- 禁止用会因重排失效的步骤编号当跨文件锚点。
