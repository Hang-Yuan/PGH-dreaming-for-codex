# Codex 原生自动化任务访谈

## 范围

记忆系统只接 Codex 原生自动化任务。部署流程不得创建操作系统任务、无界面命令行包装器或第二套调度状态。

系统只保存一条每日自动化任务：

```text
每日做梦（`daily-dream`）→ 周日条件转周级做梦（`weekly-dream`）→ 季度点条件转季度归档检测（`quarterly-archive detect`）
```

周段和季度段都没有独立自动化任务。季度归档执行（`quarterly-archive execute`）仍需用户当前会话的 C 级授权。

## 问询（三问，插在基础信息之后）

一次问一个，答完后给出完整提案并等待确认。

**问 1 · 作息**
> 你通常几点睡、几点起？

**问 2 · 时区**
> 你的 IANA 时区名是什么（例如 `Asia/Shanghai`）？

**问 3 · Codex 可用性**
> 夜间是否保持电脑与 Codex 的本地执行环境可用？锁屏、关显示器不影响任务，但别合盖——合盖默认睡眠，接电源也不解除。

自动化任务不负责关机、唤醒、合盖策略或系统电源管理。机器休眠、关机、应用退出和断网都可能造成缺勤，漏掉的日子由次日首个真人会话自动补，`week-sync` 负责断档恢复。

## 推算逻辑日界线

日界线应落在用户通常睡眠区间内，使用整点。模板默认 `06:00` 只用于未初始化状态。

推算顺序：

1. 若 `04:00` 位于睡眠区间，优先提议 `04:00`。
2. 若不在，选择睡眠区间内最接近中点的整点。
3. 固化时刻固定为日界线后 30 分钟。
4. 把「日界线、固化时刻、IANA 时区」念给用户确认。
5. 用户修正后，以用户明确值为准。手动补跑或按非默认日界线抽取时，可用 `extract_daily_transcripts.py --boundary-hour HH` 显式覆盖。

确认后同步两处权威口径：

- `.codex/AGENTS.md §时间感知`
- `<WORKSPACE_ROOT>/MEMORY/00.memory_agent.md §逻辑日期`

两处边界小时必须相同。IANA 时区写在 `AGENTS.md §时间感知`，记忆规则只留指针。

## 创建或更新唯一自动化任务

通过 Codex 原生自动化任务管理能力执行。创建或更新成功后，任务必须显示在 Codex 应用的“定时任务”页。禁止直接编辑自动化任务的 TOML 或状态数据库。

自动化任务合同：

| 字段 | 值 |
|---|---|
| 类型（`kind`） | `cron` |
| 标识（`id`） | 更新既有任务时保留原标识 |
| 名称（`name`） | 每日做梦（`daily-dream`） |
| 提示词（`prompt`） | `使用 $daily-dream 处理最近一个已经闭合的逻辑日；严格执行事务闸，并报告提交收据。` |
| 周期（`rrule`） | `FREQ=DAILY;BYHOUR=<日界线小时>;BYMINUTE=30;BYSECOND=0` |
| 项目（`projectId`） | 先从 Codex 项目列表解析 `<WORKSPACE_ROOT>` 对应的项目标识 |
| 执行环境（`executionEnvironment`） | `local` |
| 状态（`status`） | 用户确认后 `ACTIVE` |
| 模型（`model`）/ 推理强度（`reasoningEffort`） | 沿用用户为该任务明确确认的组合 |

更新前先查看现有自动化任务。命中 `daily-dream` 时原位更新；失败时保留旧任务并回报，不创建重复任务。

保存后回读，核对：自动化任务标识、名称、`ACTIVE` 状态、每日时刻、项目、模型、推理强度、`local` 环境和精确提示词。

## 首跑验收

配置验收与运行验收分开：

- **配置已保存**：Codex 返回更新成功，回读同一自动化任务。
- **日链已运行**：Codex 自动化任务历史出现该任务的计划触发终态。
- **事务已闭合**：目标日 `dream_receipts/YYYY-MM-DD.json` 为 `COMMITTED`，`last_dream.md` 指向同一天，覆盖收据与决策收据通过。

立即运行只验证日链本身。计划触发需要等待自动化任务历史出现计划触发运行。

首跑失败时：

1. 保留失败运行与梦收据现场。
2. 不推进 `last_dream.md`。
3. 修复日链或自动化任务定义后重试同一逻辑日。
4. 次日 `week-sync` 截取最近三个有效工作日的可救窗口，从最早缺日那天起逐日补跑；积压超过三个有效工作日时，窗口以前那些天的信号按接受丢失披露，不静默跳过。目标逻辑日为周日时，那一趟补跑自动含周段。

## 改作息

改作息时更新原自动化任务：

1. 重新确认日界线、固化时刻和时区。
2. 同步两处边界小时与 `AGENTS.md` 的 IANA 时区。
3. 通过 Codex 自动化任务管理能力更新同一任务。
4. 回读并确认没有第二条每日、周日或季度自动化任务。

## 机械闸

- 现役发布包不得包含 OS 调度安装脚本或包装器。
- 旧 `.pgh` 排程收据不得参与时区、日界线或任务状态解析。
- README、宪法层、技能与架构文档必须把 Codex 原生自动化任务写成唯一自动入口。
- 每日做梦（`daily-dream`）必须拥有事务与探针；周级做梦（`weekly-dream`）、季度归档（`quarterly-archive`）不拥有排程。
- 首跑成功必须由 Codex 自动化任务历史和 `COMMITTED` 地面收据共同证明。
