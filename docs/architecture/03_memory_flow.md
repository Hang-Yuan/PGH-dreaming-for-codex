# 03 · 记忆流

## 四层与一个只读源

| 层 | 文件 | 启动时注入上下文 |
|---|---|---|
| L0 · 只读源 | 会话转写 jsonl（CLI 自己落盘，零维护） | 否 |
| 情景层 · episodic | `MEMORY/episodic_memory.md`（1-3 星候选） | 否 |
| 语义层 · semantic | `MEMORY/semantic_memory.md`（4-6 星，等毕业） | 否 |
| 身份层 · identity | `USER/USER.md`、`SOUL/persona/persona_SOUL.md`、skills、宪法层 §行为规则 | **是** |

**只有身份层进启动注入。** 两个记忆池都不进——它们是代谢的工作区，不是运行时底座。运行时的共同世界模型 = 身份层三件套（你是谁 + AI 是谁 + 行为规则）。

L0 转写不是记忆文件：它完美保真、永远在场，是夜间回放的唯一输入。不维护、不注入、不清理。

---

## 白天零写入

白天工作时**不往记忆池写任何东西**。

理由是判断质量。「这件事值得记住吗」这个判断在当场做不准：一个刚发生的细节看起来总是重要的，而它是否跨周稳定、要过几天才知道。当场写进去的结果是记忆池被大量当天觉得重要、一周后毫无价值的条目填满，而清理它们比不写更贵。

故白天只做两件事：工作结论经 `close-node` 固化进工作库（详 `04_work_memory_flow.md`）；其余一切以原文留在 L0 转写里。校准信号、你的偏好、AI 判断偏了被你纠正——全都在转写里，一句不丢。

唯一例外：`close-node` 关一个节点时，如果同一节点里出现 ≥2 次独立事件支撑同一个模式，允许当场升进 episodic（N 级，留账）。这条例外的门槛是「独立事件」，不是「感觉重要」。

**道别不触发固化。** 说「晚安」「收工」不会启动任何写入链——当日工作在转写里过夜。早先的设计让告别触发固化，问题是那时你还在场、当日工作还开着：要么固化了半天的工作，要么什么都没固化而你以为跑过了。

## 夜间代谢

日界线 + 30 分钟，OS 排程无人值守跑 `daily-dream`：回放目标逻辑日的全部转写，phase A 做工作固化，phase B 做记忆代谢。

phase B 的动作：

- **升星** —— 同一模式被新证据支撑，星级上调
- **升格** —— episodic 攒够跨周稳定性，升进 semantic
- **候补 / 休眠** —— 一直没有新证据的条目退到候补，再退到休眠
- **衰减** —— 长期无支撑的条目降星，最终丢弃

全部操作写 `MEMORY_LOG.md` 留账。这份留账是唯一能回答「它为什么记住了这个」的地方——没有它，记忆池的演化就成了不可复查的黑箱。

semantic 退出启动注入之后，**代谢期是 semantic 唯一被读取的时机**。这是刻意的：它是中间产物，读它做日常判断等于拿半成品当结论。

## 遗忘是默认动作

记忆系统的默认动作是**丢弃**，不是保留。

一次代谢里大量条目被降星、退候补、删掉，是健康的表现。反过来才危险：如果什么都留着，池子会持续膨胀，而膨胀的代价不是磁盘——是每次代谢要读的量越来越大，判断越来越粗。

所以「记不住」通常不是缺陷。真正的缺陷是**该记住的没留下**，而它的成因几乎总是同一个：那件事没进转写（会话没落盘 / 排程没跑 / 那一天被跳过），不是代谢判断错了。故排程是否真的在跑，比阈值调得准不准重要得多（详 `06_cadence_and_gates.md`）。

## 上行是单向的，毕业要你确认

```
L0 转写 ──► episodic ──► semantic ──► 身份层
             ▲              │
             └──────────────┘   下行允许（衰减 / 降星 / 休眠）
```

上行单向：转写长成候选，候选长成语义，语义**毕业**成身份。下行只在池子之间发生。

毕业是唯一需要你 C 级确认的一步：

1. 你直接下令（「改 USER 某节」「把风格改成 X」）→ C 级确认
2. semantic 里某条跨周稳定 → AI 提名 → 你 C verdict → 剥壳成净描述写进身份层
3. 流程化的模式跨周稳定 → 提名转成 skill 文件 → C verdict

**没有第四条路。** 对话里说服 AI「你应该一直这样做」不会改身份层——那句话只会进转写，然后按上面的流程走。这条限制的作用是让身份层的每一次变化都有留账、有你的签字，可回溯。

完整的星级阶梯、衰减阈值、四态状态机、毕业剥壳字段在 `MEMORY/00.memory_agent.md`。
