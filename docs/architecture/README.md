面向**刚拿到这套东西、还不知道它在干什么**的人。读完这一份能回答「它是什么、凭什么这么设计」；细节在下面五份里。

## 这套系统是什么

一个人 + 一个（或多个）AI 端共用一套**文件系统即记忆**的工作库。没有数据库、没有向量检索、没有常驻服务；所有状态是磁盘上的 Markdown，所有规则也写在 Markdown 里，给读它的 AI 看。

**核心约束**：AI 的上下文窗口有限，而工作库无限增长。整套架构是对这一个约束的回答——把信息按**失效速度**分层，只让永不失效的规则与跨周有效的状态进入会话入口，其余按需下沉读取。

**因此三件事定义了这套系统**：

1. **分层**——CANON / INDEX / CONTENT 三层，入口带宽只给前两层（详 `01_topology.md`）。
2. **节律**——白天不写记忆，次晨定时把当日转写代谢成结构化记忆（详 `03_memory_flow.md`、`06_cadence_and_gates.md`）。
3. **单一权威源**——每类信息只有一处可以改，其余地方只留指针（详各篇的权威源表）。

## 全景图

```text
        ┌─────────────────────────────────────┐
        │  你（唯一 C 级裁决者）                │
        └───────────────┬─────────────────────┘
                        │
                        │  CLI 会话 / 夜间排程
        ┌───────────────┴─────────────────────┐
        │  AI 端（Claude Code 或 Codex）        │
        │  运行时目录：~/.claude 或 ~/.codex    │
        │  宪法层 + hooks + skills + agents     │
        └───────────────┬─────────────────────┘
                        │  读写
        ┌───────────────┴─────────────────────┐
        │  <ASSISTANT_ROOT>/                   │
        ├──────────────────────────────────────┤
        │ 00 专注区/    ← 当日 / 本周流水        │
        │ 01 项目区/    ← 项目本体：结论 + 推论链 │
        │ 02 阅读区/  03 写作区/                │
        │ USER/         ← 你是谁                │
        │ SOUL/         ← AI 是谁（人格）        │
        │ MEMORY/       ← 记忆池 + 代谢留账      │
        │ 长期记忆.md   ← 跨周状态与周录         │
        │ ITERATION_LOG.md ← 结构变更留账        │
        └──────────────────────────────────────┘
                        ▲
                        │  夜间：日界线 + 30 分钟
              ┌─────────┴──────────┐
              │  OS 排程 → daily-dream │
              │  phase A 工作固化      │
              │  phase B 记忆代谢      │
              └────────────────────────┘
```

会话转写（CLI 自己落盘的 jsonl）是**唯一的原始输入**，不由本系统维护。白天只往工作库写结论，不写记忆池；记忆在夜里由排程从转写里长出来。

## 权威源索引（本说明书只指向，绝不复述）

| 想知道什么 | 去哪 |
|---|---|
| 全局宪法：启动序列 / 思考协议 / S-N-C 分级 / 时间感知 | `AGENTS.md`（Claude 端 `CLAUDE.md`） |
| 记忆系统全部规则（结构 / 判准 / 阈值 / 授权） | `MEMORY/00.memory_agent.md` |
| 某一区的写入标准与越界特征 | 该区 `00.{区域}_agent.md` |
| 你的身份特质 | `USER/USER.md` + 其子文件 |
| AI 的行为风格 | `SOUL/persona/persona_SOUL.md` |
| 单个 skill 怎么跑 | 该 skill 自身的 `SKILL.md` |
| 排程访谈的问法与推算规则 | `docs/schedule_interview.md` |
| 任何结构变更的历史与理由 | `ITERATION_LOG.md` |

## 描述层声明

本目录是**描述**——这套系统实际怎么运转；上表各权威源是**规定**——应该怎么做。

- 描述层过时不算违规，算待更新。
- **规定层与描述层冲突时以规定层为准**，并同轮修描述。
- 故：照本目录改系统是反的。要改行为，改权威源，再回来修这里。
