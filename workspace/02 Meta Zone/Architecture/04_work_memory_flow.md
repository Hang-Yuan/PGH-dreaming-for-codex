# 04 · 工作固化

记忆流（`03_memory_flow.md`）管「AI 学到了什么」；本篇管「工作推进到哪了」。两个系统分开，互不复述。

---

## 结论落在哪

| 信息 | 权威源 |
|---|---|
| 项目结论 | 该项目主文档（`_current.md` 只写指针） |
| 项目推论链 | 项目目录下 `_progress/` 的节点文件 |
| 当前处境 | `Long_Term_Memory/status.md §当前处境` |
| 跨周推进（从 X 到 Y） | `Long_Term_Memory/weekly.md` |
| 当日流水 | `00 Focus Zone/_current.md` |

**`_progress/` 是过程附件，不是结论的主文档。** 这条最容易搞错：推导写进 `_progress/` 之后，结论必须**同时写回项目主文档本体**。只写 `_progress/` 的结果是主文档停在三周前的状态，而最新结论埋在一个按时间命名的节点文件里——下次进这个项目时读主文档，读到的是过时的判断。

对称地，`_current.md` 里只放指针与流水，不放结论本体。它每周归档；结论跟着归档走就等于丢了。

---

## 两条固化路径

**小时级 —— `close-node`**：一个节点在对话中明确闭合时立刻固化。

「明确闭合」是指这一段推导有了结果、可以写下来了，不是「聊完了」。它写项目主文档的结论节、写 `_progress/` 的推导链、在 `_current.md` 留指针。N 级：直接做，事后报。

**夜间 —— 每日做梦（`daily-dream`）A 段**：把目标逻辑日的**全部**工作固化进工作库。

它读那一天的全部转写，不依赖白天有没有及时调 `close-node`。这是兜底：一天里大部分推进不会有明确的闭合时刻，它们只是发生了，然后被下一个话题接上。没有这道全量固化，这些工作就只存在于转写里，而转写不是工作库——下次进项目时没人会去翻它。

两条路径不冲突：`close-node` 让重要节点即时可见，A 段保证没有工作只因为「当时没想到要记」而丢掉。

---

## 逻辑日期口径

固化跑在夜里，处理的是**刚闭窗的那个逻辑日**——不是日历上的昨天。

逻辑日的边界叫**日界线**，由你的作息决定，部署时装排程那一步问出来（详 `docs/schedule_interview.md`）。物理时刻早于日界线的，算前一天。

举例：日界线 06:00 时，凌晨 04:00 干的活算前一天的账；日界线 03:00 时，同一个 04:00 已经属于新的一天。

**这个值不能用默认值糊过去。** 设错不会报错，只会每天都有一段工作被归到错误的日子——而错的方式是稳定的，你会看到「每天早上那几个小时总是记在前一天」，但不容易意识到是日界线设歪了。故它在部署时被写进两处口径行（宪法层 + 记忆区权威源），由执行部署的 AI 同步修改，保证两处同数。

## 周段

目标逻辑日是周日的那一趟，每日做梦条件转调独立周级做梦（`weekly-dream`）：

- 把 `00 Focus Zone/` 本周流水归档进 `_archive/`
- 往 `Long_Term_Memory/weekly.md` 写这一周「从 X 推进到 Y」
- 账实核对：专注区里有没有文件没被纳入 `_current.md`
- 记忆池容量检查：满载不降时强制清理

**周段跑在周一凌晨**（那一趟的目标逻辑日是周日）。所以「周录什么时候写」的答案是「周一凌晨自动写」，不是「周日晚上你记得写」。

周级做梦不另装排程、不重读一套日级入口，也不单独推进探针；它的回执并入父级日事务。季度点再条件转调季度归档检测（`quarterly-archive detect`），只清点并挂待裁；执行模式（`execute`）仍等用户在当前会话明确授权。

---

## 断档怎么处理

排程没跑（机器关着 / 合盖睡眠 / 装坏了）时，当天缺口由探针与事务收据显露。

次日第一个真人会话的周同步（`week-sync`）核对昨夜事务，查出断档就在后台派单补跑。它先截取最近三个有效工作日的可救窗口，再在窗口内从最早缺日开始逐日、一次一天执行；窗口以前的信号按接受丢失披露。补跑走的是同一条每日做梦链，读的是同一份转写，故结果与当夜自然跑一致；失败时不推进探针。

**但补跑不算「排程装好了」。** 首跑验收刻意把两者分开：补跑写不出排程自己的自然运行凭据。理由是这两件事的后果不同——排程真的在跑，你什么都不用做；排程没装成而你每天靠补跑，忘一次就静默丢一天。配置凭据与自然运行凭据分别见 `06_cadence_and_gates.md §配置证据`、`06_cadence_and_gates.md §运行证据`。
