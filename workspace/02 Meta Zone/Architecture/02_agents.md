# 02 · 分工

## 为什么要分子代理

不是为了并发。是为了**保护主会话的上下文带宽**。

主代理的上下文里装着身份层、当前工作状态、这一轮的推导链。往里灌一份 800 行的日志、或者十个文件的全文，推导链就被挤出去了——表现是它突然「忘了」十分钟前说过什么。

故凡是**重型文件读写、低判断**的活都派出去：子代理在自己的上下文里读完，只把摘要带回来。主会话拿到的是结论，不是原文。

同理，凡是**结果需要验证格式**的写入也派出去：由子代理读目标区规则后落盘，主代理只审回执。

---

## 默认内置的子代理

模板自带两个，覆盖最常见的两类外派：

| 子代理 | 干什么 | 什么时候派 |
|---|---|---|
| 通用检索代理（`general-search-agent`） | 网页检索、对话回溯、信息整理 | 需要外部事实、或要回看很早的对话 |
| 存储代理（`storage-agent`） | 本地文件读写代理：批量 / 长文件读取 → 摘要、长文件与日志落盘、归档 | 一次要读很多文件、或要写很长的东西 |

需要别的领域（学术检索、尽调、特定业务）时，在运行时目录的 `agents/` 下新增一份。**子代理的价值在于带回已经消化过的结论**；把原始数据整份贴回主会话会抵消分工收益。

---

## 主代理做什么、不做什么

**做**：判断、推导、裁决派单、审回执、跟你对话。

**不做**：

- 不直读超预算额度的文件——派子代理读回摘要（详 `01_topology.md §三层信息模型`）。
- 不直写索引层（INDEX）与身份层——发载荷给子代理，由它按区规则写。
- 不在讨论态动文件——没收到「开始做 / 动手吧 / 执行」这类显式信号，默认还在讨论。

最后一条最容易被忽略：方案在讨论中频繁修正是常态，过早执行是把还在流动的方向提前凝固。执行错了可以改，但你会开始防着它乱动，于是不再放开讲——那个损失不可逆。

---

## S / N / C 三级授权

每个动作按**可逆性与影响面**定级，决定要不要先问你：

| 级 | 含义 | 例子 | 怎么做 |
|---|---|---|---|
| S · 静默 | 低风险、可逆、局部 | `_current.md` 追加一行 | 直接做 |
| N · 通知 | 中风险、影响可见，或需要事后可见回执 | 记忆池条目级操作、项目主文档结论节、`Long_Term_Memory/status.md` 更新 | 直接做，事后回报 |
| C · 确认 | 高风险、不可逆 | 改 `USER` / `SOUL` / 技能、删除或覆盖整份权威源 | 告知 + 等你确认 |

**身份层（USER / SOUL / 技能）只在你 C 级确认后才写。** 这条是硬的：身份层决定 AI 以后怎么行动，让它能被对话直接改写，等于让它自己改自己的行为准则。记忆池条目可以自治（写了留账、你随时能推翻），身份层不行。

---

## 夜间无人值守时的分工

排程运行每日做梦（`daily-dream`）时你不在场，故那条链里**没有 C 级动作**：需要你确认的事一律写成提案留着，等你下次会话看。

这不是限制，是必要的：无人值守时「等确认」等于永久挂起，而挂起的表现是那一段静默不执行。写成提案则下次会话一定会被看到。

链里的 A 段（工作固化）与 B 段（记忆代谢）都在 N 级以内，全部操作留账（详 `03_memory_flow.md`、`04_work_memory_flow.md`）。
